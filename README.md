# ls-massage — «Линия спорта» / массаж

Сайт: **https://massage.liniyasporta.ru/**

Этот репозиторий предназначен для исходников сайта массажистов двух клубов «Линия спорта» и последующей публикации на REG.RU. Каждый сайт проекта находится в собственном репозитории.

## Важно: текущее состояние

- Репозиторий **публичный по решению владельца**; материалы сайта предназначены для открытой публикации. Пароли, токены, приватные конфигурации и закрытые материалы сюда не добавлять.
- Последняя подготовленная редакция сайта: **v11 от 17.10.2026** (материалы сохранены в приватных источниках проекта). **Исходники v11 ещё не перенесены в этот репозиторий**.
- Проверка FTPS №1 завершилась **ошибкой `530 Login incorrect`** (17.10.2026): секрет в этом репозитории обнаружен, но сервер отказал в авторизации `u3652448_massage`. Сверьте учётную запись FTP и пароль в ISPmanager; **не сообщайте пароль в чат**.
- Наличие GitHub Actions **не означает**, что DNS, SSL, серверный каталог или FTP-учётные данные уже проверены.
- Автоматическая публикация **выключена**; все операции запускаются **вручную**.
- Пока сайт не перенесён и не проверен, `site/index.html` намеренно отсутствует: загружать пустой/устаревший сайт нельзя.

## Сценарии GitHub Actions

1. **Check massage FTPS (read-only)** — проверяет пароль и доступ к выделенному FTP-пользователю, ничего не изменяя на сервере.
2. **Deploy massage to REG.RU (manual, guarded)**:
   - `mode=plan` — проверка обязательных файлов сайта, защитного маркера на сервере и сухой прогон загрузки (**без изменений**).
   - `mode=deploy` — после подтверждения домена, проверки маркера, резервного копирования **только публичных файлов** в артефакт GitHub Actions и без удаления существующих серверных файлов загружает `site/` и проверяет HTTPS. Поскольку репозиторий публичный, резервная копия не должна содержать конфигураций, скрытых файлов и секретов.

## Подготовка хостинга

1. В ISPmanager проверьте, что `massage.liniyasporta.ru` создан как **отдельный** сайт с правильной папкой и HTTPS.
2. Убедитесь, что FTP-пользователь `u3652448_massage` имеет корнем **именно** публичную папку этого сайта — не общий каталог хостинга.
3. В файловом менеджере ISPmanager положите в **корень этого сайта** текстовый файл `.massage-site-root.txt` с единственной строкой:
   ```text
   massage.liniyasporta.ru
   ```
   Этот файл — защитный маркер. Без него deploy и plan не продолжатся.
4. В GitHub → Settings → Secrets and variables → Actions добавьте в **этот** репозиторий `MASSAGE_REG_PASSWORD`.
5. В GitHub → Actions запустите read-only FTPS-проверку. Затем перенесите *полный* комплект v11 в `site/` (HTML, CSS, JS, `content.json`, фото и оригинальные логотипы).
6. Выполните `mode=plan`; изучите список предполагаемых операций. Только затем вручную запускайте `mode=deploy` с подтверждением домена.

**Ничего не удаляется с сервера автоматически.** Сценарии не включают `--delete` и не запускаются при push.
